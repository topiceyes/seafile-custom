# 025 - 独立部门共享空间实现（1.3.0）

日期：2026-11-04。状态：本地实现和开通完成；生产尚未升级。设计见 [024](024-department-spaces-design.md)。

## 已实现

- 独立 `department_spaces` Django app 和 Web“部门共享”入口，新增空间不会创建 ccnet 群组。
- 每个业务部门一个普通 CE 资料库，由随机密码、非管理员的部门托管身份持有；成员和主管通过原生用户共享获得 rw 权限。
- 直属成员只访问本部门；主管管理本部门及全部后代。根部门主管如已配置，按相同规则向下继承。
- 部门改名跟随更新，换父级重新计算主管权限，保留 repo_id；主管降级或人员离开后回收权限。
- 首次钉钉登录按最后一份完整组织快照补授权；未开通 Seafile 账号的人员保留组织任职关系。
- 主管可维护空间说明、查看回收站和恢复项目；管理动作记录真实操作人。主管不会成为全站管理员。
- 管理员可在同一入口查看全部空间状态，不因此自动进入每个部门的文件访问名单。
- 用户群组和共享目标中排除已开通空间的旧钉钉部门映射；手工群组保持原用途。
- 旧个人资料库按原访问权限显示于“历史共享资料”，不自动转移 owner；旧群组只维持已有共享兼容，不再新增。
- 新部门库在 Web 通用列表去重；原生客户端的资料库发现接口保留兼容共享类型。
- 新旧分享入口限制部门库公开链接、上传分享链接、再共享、转移和独立库 token；正常文件上传用的单数 `upload-link` 不拦截。
- 中英文 UI 文案，生产镜像编译对应 gettext 目录。

## 同步和失败处理

新命令：`sync_department_spaces`。现有 cron 使用的 `sync_dingtalk_departments` 保留名字并委托新命令，避免安装了旧 cron 的机器继续创建群组。

```bash
# 在容器内运行；生产镜像提供此入口，它校验 Python 成功标记
/usr/local/bin/seafile-management-task sync_department_spaces --dry-run
/usr/local/bin/seafile-management-task sync_department_spaces
/usr/local/bin/seafile-management-task sync_department_spaces --reconcile-only
```

特点：完整拉取部门、直属成员、主管后再提交快照；连接/读取超时和瞬时错误重试；互斥锁避免并发全量任务；数据库行锁保护开通和登录补偿。先撤权再加权，失败状态持久化，幂等重试修复实际文件授权。

部门数、任职关系或授权撤回超过 25% 时中止。确认通讯录权限范围正确且变更为业务事实后，可以显式加 `--allow-large-changes`。这是一道数量异常保护，不能替代钉钉应用全员通讯录授权。

真实接口取证发现：钉钉成功的部门详情会省略空主管列表，空成员分页也可能省略 list；适配器在校验返回码和部门 ID/名称后做空集合归一化，不把整体响应失败当作无人。

同时发现上游 `seahub.sh python-env` 在 Python 报错后仍执行 `echo Done.`，最终退出码为 0。新增 `seafile-management-task` 入口，要求完整的一行成功标记，确保 cron 不再把包装脚本成功当成命令成功。离职同步 API 错误与空集合改为 CommandError，并增加请求超时。

## 迁移与部署

- 增加 `department_spaces.0001_initial`，只新增本模块的表。镜像启动在配置生成后、Web 服务前迁移该 app，失败阻止启动。
- 镜像烘入新任务入口；dev compose 增加同一脚本挂载，首次更新开发环境需要重建容器或安装该入口。
- 不删除旧部门群组，不自动把原个人库转为部门资产。迁移台账和负责人确认后再退役旧数据；历史个人库的主管访问仍取决于原始共享权限，不自动因新空间主管继承而扩大。
- 部门在完整快照中撤销后标记 archived，撤回新部门库的日常授权并保留资料。旧个人共享涉及原 owner，暂保留兼容关系供人工归档。
- 当前组织来源沿用现有单钉钉应用部署；不提供跨组织合并和同部署多来源空间。
- 同步周期仍为每小时；首次登录补偿不代表钉钉变更实时推送。
