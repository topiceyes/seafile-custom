# 027 - 部门共享中文语言包修复（1.3.1）

日期：2026-11-04。

## 问题与修复

部门共享的中文词条已经写入 `locale/zh_CN/LC_MESSAGES/djangojs.po`，但 1.3.0 镜像只编译了 `.mo`，没有运行 `compilejsi18n`。React 页面从 `media/assets/scripts/i18n/zh-cn/djangojs.js` 加载的是官方镜像留下的旧静态目录，新文案查不到翻译，因而显示英文。

构建现在按 `.po → .mo → compilejsi18n → collectstatic` 的顺序重新生成中英文语言包。React 基础页及三个文档查看模板改用 Django `static` 标签取得内容哈希地址，替代仅随上游版本变化的 `?v=14.0.9`，避免浏览器继续缓存旧词条。

用户选择简体中文后，部门共享入口、身份、状态、查找部门、空间说明、主管与成员列表、历史共享提示和回收站按钮使用已有中文翻译。用户的语言选择仍按原有设置生效，不强行覆盖其他语言偏好。

## 验证

- 旧镜像在新增检查中复现 `Access pending` 缺失，证明检查能够识别本次故障。
- 检查浏览器实际读取的普通路径与内容哈希文件是否一致，逐项对比中英文 `.mo` 与 JavaScript 目录中的单数词条。
- 以生产使用的 `ManifestStaticFilesStorage` 渲染四个模板的语言包片段，核验实际输出的内容哈希 URL。
- 语言包检查加入统一镜像冒烟，与 32 项部门业务回归和 4 项任务包装回归一起运行。

无新数据库迁移，不改变部门成员或主管权限规则。发布与镜像 digest 以 GitHub Release 记录为准。
