# 部门空间共享权限检查与加固

## 范围和结果

部门资料库由组织同步授权；部门成员、主管及管理员都不能通过普通共享入口另行创建访问授权或转移该资料库。同步服务自己的授权、撤权使用 `SeafileBackend` 的专用 RPC 路径，不经过普通分享操作。

静态审阅发现旧版私有共享、批量资料库共享和分享邀请没有被既有 URL 片段规则完整覆盖；这不等于普通成员已能绕过上游所有者/管理员检查。现增加以下防线：

- 普通资料库和文件夹共享、共享权限修改的公共函数，以及旧版私有共享入口，在执行 RPC 前检查部门库。
- 批量共享对每个部门库返回失败；同一请求中的其他个人库可继续处理。批量取消共享保留，用于清理旧授权。
- 分享邀请、公开下载链接、公开上传链接和资料库 API token 在模型保存时拒绝部门库。URL 中间件同时覆盖旧版共享、邀请与管理员共享入口，并检查重复的表单库 ID。
- 统一的资料库转移函数拒绝部门库，避免部门库所有权脱离组织管理。

这些措施覆盖本次检查的路径，不声称覆盖所有上游、插件或 RPC 入口。现有历史外链、邀请、资料库 token 和手动授权不会被本次代码自动清除，必须盘点并制定处理方案；服务端直接 RPC 和数据库访问也不经过 Web 策略。

## 验证和限制

`deploy/image/test-department-policy.py` 在隔离替身下执行实际共享/转移函数及批量入口，检查部门库拒绝发生在 RPC 前，混合批次的个人库仍能共享。部门空间 Django 测试增加了旧版共享、邀请、管理员共享、重复表单参数和 JSON 数组的检查；既有测试覆盖成员、主管、无关部门、撤权和失败重试。两套检查接入镜像冒烟。

2026-11-05 本地新构建的 arm64 镜像通过完整冒烟：部门空间 Django 测试 37 项、共享策略隔离测试 5 项、客户端 SSO 测试 11 项。真实钉钉同步、WebDAV 与桌面客户端的端到端访问/撤权仍未实测。目录同步每小时执行，失败或触发大变更保护可延长权限保留时间；已有文件传输凭证、客户端缓存及历史公开链接的失效时效也需要在隔离环境实测。生产使用前应完成真实服务的权限矩阵和撤权演练，并核查历史授权。
